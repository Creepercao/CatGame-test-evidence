Stopwatch为方法调用墙钟耗时，包含等待/系统调度，非纯CPU。首次CG表示每轮进程内首次Resources.Load，未清操作系统文件缓存；两轮不是冷盘对照。暖CG不是一次玩家停留几十秒的体验。

可证实的定位层次：每帧存读压力中，SaveToPath方法边界均值高于LoadOrCreate，两轮约为4.4/4.3倍，写路径是这个负载的主要墙钟热点；读取也出现228.293ms单次长尾。方法分布支持这个结论，不能进一步断言某一次File.Replace、序列化、杀毒扫描或磁盘是根因。没有CPU调用栈、I/O trace或GC分配调用栈来支持这些更细结论。

源码审查可提出解析正则缓存/临时对象等假设，但不能替代Profiler验证。稳定玩法门槛已满足，本轮不为生成“优化成绩”取消原子写入/备份安全或臆测改实现；未做游戏性能改动，第二轮是重复基线，不能计算成优化收益。真实自动保存周期与逐帧1000存读不同，后者在当前方案作为压力观察。建议后续仅在实际保存卡顿需求成立时，加I/O/CPU调用栈定位，再同条件A/B及存档完整性回归。

## 复现和学习

在项目根目录、没有Editor/游戏/CI负载时执行，每次指定新的结果目录：

```powershell
python tools/qa/run_unity.py --output Tests/robot/results/performance-build-new --method CatGame.EditorTools.CatGameSetup.BuildPerformanceQA
python tools/qa/run_suite.py --profile performance-probe --output Tests/robot/results/performance-probe-new
python tools/qa/run_suite.py --profile performance --output Tests/robot/results/performance-baseline-new
python tools/qa/run_suite.py --suite Tests/robot/tests/performance_guard.robot --output Tests/robot/results/performance-guard-new
python tools/qa/audit_performance.py --run Tests/robot/results/performance-baseline-new --guard Tests/robot/results/performance-guard-new --output Tests/robot/results/performance-audit-new
```

每条命令通过并检查数据后再继续，失败不得靠重复直到绿替代定位。先读方案/环境，再从单猫CSV手算P95和慢帧比例，接着解释100猫CPU增长但帧P95接近的原因，最后追读保存逐操作尖峰。源码顺序：performance.robot → run_performance.py → PlayerPerformanceQA.cs → performance_stats.py → audit_performance.py。

目前没有GPU耗时、Profiler调用栈、长期内存对象快照、多设备/多分辨率性能、热稳定性或移动端结论。用户负责目标、需求和范围决定；AI协助实现、执行、分析与成文。这些交付可以作为学习和作品证据，不能直接宣称用户已独立掌握所有定位技能。
