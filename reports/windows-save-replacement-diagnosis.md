## 原始游戏路径复现

在没有编辑器运行时，以 Unity CLI 1.0.0 / Unity 2022.3.21f1 运行完整 EditMode，最多计划三轮，首次失败即停止。环境 TEMP/TMP 使用 `Build/Android/build-temp`，Editor 存档隔离到 `Build/SaveDiagnosis/editor-save`，`CATGAME_SAVE_FAILURE_ROOT` 指向独立诊断目录。

`Build/SaveDiagnosis/repeat-01/EditMode-1.xml` 为 61/62，唯一失败为原千次存档压力用例第 969 轮，HResult=0x80070497。Unity 进程退出 2、CLI 退出 8，未将 XML 和进程退出码混为同一层。随后两轮未执行，不计通过。

异常时复制的现场：主档 clicks=968，备份 clicks=967，临时文件 clicks=969。三个文件均可解析。它证明这一次替换失败保留了上一份已提交主档，不证明所有 I/O 故障均能保留数据。`save.bad.json` 是该用例第 499 轮主动注入的损坏数据，也保留在现场副本中。

此前排序：其他用例/顺序干扰；已有备份的替换；Windows 短暂占用或系统文件操作条件。未给具体占用进程下结论。

## 有限重试诊断

新增 `tools/qa/windows_replace_probe.py`，默认不重试且失败退出 1。另用 `--retries 3 --delay-ms 10` 做诊断：只对 1175、且主档和临时文件字节均保持的条件最多重试三次，所有错误事件仍逐项记录，成功后核对备份字节等于上一份主档。不是把每轮失败无条件改为通过，也没有把该策略加入游戏。

执行命令：`python tools/qa/windows_replace_probe.py --output Build/SaveDiagnosis/native-retry-01 --retries 3`。结果按每组实际完成数、错误事件数、是否恢复分别统计；未执行到的组不计入。

七项覆盖短暂 1175 分别失败 1/3 次、有/无备份共四项；持续 1175、共享冲突 0x80070020、其他替换错误 0x80070498 共三项。red.xml 为 2/7 通过、5 项失败，Unity 退出 2、CLI 退出 8；两个本来就符合的其他错误传播用例通过。
